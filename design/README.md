# Design

Working that PLAN.md used to carry inline. PLAN.md is loaded into every session,
so it holds decisions, schema, status and open questions — not the argument
behind a finished change or an unbuilt feature. That argument lives here.

The distinction from `research/`: those files are **inputs to decisions**,
gathered from outside (the spec, distribution, zot, real clients). These are
**records of our own design** — one finished, one not yet started.

| File | What it is |
|------|------------|
| `analytics.md` | Feasibility sketch for pull counts and tag history. Nothing decided; read before starting package J. |
| `applied-schema-changes.md` | The `research/R4` schema batch, all of it already applied. Read when you want to know why a field exists. |
